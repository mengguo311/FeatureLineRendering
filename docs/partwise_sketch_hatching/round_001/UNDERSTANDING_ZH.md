# 首轮理解与证据边界

已逐行阅读用户大纲第 1–851 行（§0–17），先读执行 BRIEF。本文件在实验实现与评测前写入。大纲中的数量、阈值与周期均为建议，不是实验成绩。

目标（§0–1）是可编辑的分部 NPR 物体：选择稳定三维部件，改变方向、疏密、长度、粗细或交叉方式；其他部件保持不变，相机变化时笔触贴附表面并正确遮挡。输入主路线为 RGB 与相机，允许少量点击与人工修正。第一轮仅执行 CPU，不训练 RaDe-GS。

四层必须分开（§0、3、4）：表面及稳定部件 ID；固定实体结构曲线；随视角变化的轮廓及遮挡边界；由风格规则生成的表面排线。圆环可以是实体结构，但球体轮廓不是固定三维线。排线不拟合照片边缘；阴影和高光不能默认成为结构线。标签边界也不必是几何锐边。

假设优先级（§2、8、11）：H1 是稳定部件与表面附着的基础，必须有 B0 或独立对照才能证明改善；H2 是粗分部与噪声重建下结构线—边界—方向关联的研究候选，先做同标签 B1/B2/B3；H3 贡献追踪仅用于困难固定结构线，须胜过最佳单深度及等预算扰动，oracle 上限不能当方法成绩；H4 同路径线高斯后端须证明质量／速度收益；H5 几何反馈须有独立几何或留出视角证据。首轮不启动 H2–H5，不恢复旧 K=3 核聚类。

P0（§3.3、5.5–5.8、6.1、11、14.3）需建立坐标、光轴深度／射线距离转换、法线、方向退化回退、无向线场、确定性种子、三角形重心锚点、遮挡及能响应故障的指标。P1 最小目标（§0、7、11）是灯罩／支杆／底座，三种风格配置，以及真实三维路径逐相机渲染的旋转、缩放和单部件编辑视频。首轮只承诺 GT fixture 的端到端演示与局部编辑，不能将它称为已完成 RGB→RaDe-GS→点击分部的主系统；完整交互 UI、五类编辑、光照视频和嵌套 LOD 后续另做。

证据边界（§5.1、6、8.2、9）：参数化台灯的网格与标签来自已知设计，是解析 GT 诊断，不是重建代理。网格内重心锚点误差仅验证实现；另用独立解析曲面求距离／射线遮挡作 fixture 检验。所有人工方向规则、GT 部件、已知实体环均公开。真实 RaDe-GS 必须具备作者代码、训练来源、检查点、训练视角深度融合及固定快照，旧 vanilla GS PLY 不得改名。未找到灯数据不等于全磁盘不存在。历史已暴露的 Ficus/chair/lego/drums 视角不能称 blind。

评测（§9–10）：编辑泄漏用独立解析可见部件掩码，同时报告目标内非零变化、固定 2 px 边界带、其他部件远区与背景。报告所有固定视角。实际图像中心线支持误差只作渲染诊断；未完成独立逐笔触对应、共同可见覆盖与消失／重现分析时，时序稳定性标为 UNMEASURED，不能用坐标不变或视频可解码代替。输出实际 CPU 时长，不宣称 1024/24 FPS。对象只有一个、种子一个，不能推断统计显著性或跨对象泛化。

实现选择（§5.6、13–14）：自建旋转曲面三角网格，通用三角邻接行走，三角形 ID＋重心坐标保存路径。显式曲线、网格和人工／GT 标签均合法。固定环来自已知 fixture 设计，不从图像恢复。渲染独立实现三角形 z-buffer、逐样点深度测试和 2× 超采样；不能用二维旋转／缩放冒充三维相机运动。

资源与阻塞：仅当前授权 worktree/branch 写源码、测试、配置和报告；大输出写指定 round_001。CPU 两核、无 CUDA、单次运行上限 10 分钟，空闲盘和输出上限检查。RaDe-GS GPU 训练在本轮明确阻塞，现有作者代码／检查点／灯 RGB+相机的实际可用性由资产清单记录。协议先提交，执行后不改阈值、不筛坏视角；失败保留，下一轮只推荐一个独立且可防守的进展。
