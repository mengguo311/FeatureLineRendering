- round_001 全科学输出后 JSON NumPy 标量汇总失败；外层 rc=143，Python 子进程退出码未独立捕获。round_002 实际 runner rc=1，后续只读数据验证 rc=0；不能改写原退出码。
- round_002 的 6 条 mixed、26 条 parallel、57 条 cross 笔触因方向不相容／歧义短于请求长度；最复杂底座路径仍有 717 个锚点。循环消失不等于风格质量解决。
- 原两处 azimuth=30° 灯罩上缘深度离群点 `(185,95)`、`(327,95)` 保留，max 约 0.130758 世界单位。不能扩大 2 px 评价带遮住它们。

- round_012 有限像素中心门控不能匹配部分物理可见面积，NO_GO；round_013 重复遮挡三角形导致 occluded 诊断数组最大约 7.6e-15 差异，严格相等门槛失败，NO_GO。后续有限域修复不能改写这些历史结论。

实际视觉检查：round_001/002 的四视角全灯都在画面内，灯罩／短细支杆／底座可辨，风格有明显区别。支杆局部黑线堆积、底座短交叉杂乱、cross 局部过黑及随机间距不均仍可见。round_002 相对 round_001 的整体变化较小。round_016 只有低分辨率两段直线及遮挡缺口，候选/参考相同、差异栏空白，线段仍有阶梯和浅尾。接触图阅读不能证明视频无闪烁。

## 旧宽度审计是否是整灯集成前置条件

**不是。** round_016 NEXT 的 1→2 px 单带宽度审计适用于其 `planar_fragments_exact` 有限域后端；当前 BRIEF 明确允许在它不再是整灯路线前提时跳过。该后端限定平面、常深度分离三角形和单一直带，完成该审计也不能证明弯曲全灯的遮挡与局部编辑。新单元采用独立冻结的通用网格／带状曲线深度测试路线时，直接在全灯上验证非零目标变化、独立部件掩码泄漏和三部件可见性更有应用价值。跳过应记为 `NOT_RUN / NOT_REQUIRED_FOR_SELECTED_BACKEND`，绝不能记成 width audit GO。

旧 `core.render` 的缺陷不能原样宣称解决：先将点投影取整，用点深度比较另一个取整像素射线的表面深度，再做宽度最大滤波；这混合了可见性与覆盖。round_004 上缘 256 个 exact-ray 可见点因取整射线差异 0.006077–0.019346 被拒绝；其他两个 ID 中确有真自遮挡，不能简单放大 0.006 容差。通用替代应在同一光栅样本位置计算笔触覆盖、表面深度及 owner/part；超采样是近似而非解析面积证明，必须这样标注并在实际全灯输出检查。

## 本单元建议与后续距离

优先复用已修复的 GT 台灯／稳定锚点，冻结相机、三种部件风格、编辑、掩码、边界带与图像质量要求后运行整灯。可在 DEV 证据上处理杂乱与间距，但所有旧视角／路径必须标为已曝光，不能伪装新盲测。保留原始输出、非目标 ID/坐标、非零目标响应、深度前后遮挡与故障注入。实际光栅的时序验证要报告支杆、遮挡及重合排除覆盖，不能只给全局平均。

P1 的下一步是完整对象渲染及编辑的真实运行与可视检查，然后锁定 orbit/zoom/edit 视频、完整解码和逐部件渲染时序证据；不是再次建立平面证明链。真实 RaDe-GS 输入另列桥接任务，CPU 禁止训练是资源阻塞而非 GT 工程集成阻塞。
