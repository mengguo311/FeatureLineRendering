# 3DGS 边缘研究的 Agent 执行入口

请先完整阅读同目录的 [研究大纲](3dgs_edge_control_research_outline.md)，再开展实现。文献已调研，算法与实验尚未实施。研究目标是在带实例标签的静态 3DGS 中，识别可见三维邻近区域的 Gaussian 贡献，用过渡宽度、对比和连续强调场控制边缘，区分真实感修复与主动风格化。

## 开始执行

1. 检查当前项目、适用指令、Python/CUDA/GPU、磁盘和可用数据。读取原始 3DGS、Gaussian Grouping 与 COB-GS 官方实现的相关入口，记录版本。普通实现选择自行处理，不需要反复确认。
2. 优先复用项目已有底座，避免同时引入多套 renderer。若没有底座，先复现一个标准 3DGS 场景；无训练 GPU 时完成合成数据、剖面测量器和文档可运行部分，明确记录训练尚未执行。
3. 首先实现 P0–P3：渲染诊断接口、稳定 Gaussian uid、空间候选、实际合成贡献、边缘剖面测量、硬边修复和消失边 no-op。先做一个场景的完整闭环，再扩展 MVP。
4. 必须先测 B0 原模型、B1 等预算普通局部微调、B3 统一处理、B4 COB-GS 和 B6 仅二维 band 选择。指标正确、基线可复现后，才测试本文拟议控制。
5. P0–P3 通过后继续软边和三维绑定断续场，并补足大纲要求的相关强基线。若复杂方案不优于等预算简单方法，先报告原因与负结果，再决定是否需要 renderer 扩展。

## 必须保持的研究约束

- 真实表面接触、Gaussian 等值范围重叠、二维遮挡轮廓是不同对象。隐藏接触区的外观标记 unknown。
- 硬软、消失和断续是不同属性轴。低对比时宽度允许不可辨，不强制四分类。
- 候选集合没有天然唯一的 kernel 真值；使用清楚定义的表面、像素和贡献代理评价。
- 观测状态、诊断假设与人工目标分别保存。真实 RGB 上不要声称唯一识别了失焦或物理接触原因。
- 数据拆分和目标场预先固定。测试视角只用于评分，不能参与诊断、操作选择和超参数拟合。
- 固定实例标签后再优化边缘，防止通过改标签降低渗漏损失。拆分后保持 uid 来源、实例标签和 anchor。
- 弱化边缘不等于降低 opacity；不能用孔洞换取软边、消失边或断续效果。
- 保留抗锯齿；如果修改裁切后的 alpha，必须重新计算后续透射权重。
- 所有收益按任务 A 和任务 B 分开报告，并比较相同数量上限、相同时间预算。
- COB-GS、DisC-GS、DRK 和 LocalGaussStyle 是直接先行工作，不能把边界拆分、裁切、锐度控制或防风格泄漏单独宣称为首创。

## 运行和交付

按照大纲第 13 节建立代码、配置与结果结构。每个阶段保存实际命令、参数、源码 commit、数据划分、种子、训练日志、指标与失败样例。只把完成并验证的程序标记为完成；禁止用占位图、虚构数字或预期结果代替实验。

最终提交代码与复现说明、文献对应表、分场景基线结果、候选可视化、边缘放大图、测试路径视频、消融和失败分析。正式测试前根据 pilot 冻结成功门槛，正式结果出来后不得反复修改门槛。
