## Input audit and camera domain

Official sources, read 2026-09-30: [download](https://cvg.cit.tum.de/data/datasets/rgbd-dataset/download), [file formats](https://cvg.cit.tum.de/data/datasets/rgbd-dataset/file_formats). Extracted sequence has no README or intrinsics file. Its three comment headers identify rgbd_dataset_freiburg1_desk.bag. Archive checksum is the user's already verified e983d6830916e66dc4a46a71368046b149b283de87769690e7aa4e0b9483530c; do not reread the combined archive.

RGB is 640x480 8-bit; sensor depth is registered 640x480 uint16 from a separate Kinect IR sensing channel, not GS render depth. Divide by 5000 to get optical-axis metres; zero means missing. The fr1 1.035 correction is already applied. Use the official recommended ROS defaults fx=fy=525, cx=319.5, cy=239.5, without additional undistortion. fr1 measured RGB calibration differs (517.3,516.5,318.6,255.3 with nonzero distortion); default registration residual is a documented grey area, not a parameter to fit on C. Mocap poses are RGB optical centre camera-to-world in metres, xyzw quaternion. These independent poses are not an accuracy certificate: interpolation, motion blur, IR/RGB timing, reflectance holes and residual registration can invalidate structure.

INPUTS.json stores every selected pose and association before pixels are read. Greedy RGB-order nearest unique depth <=20 ms; interpolate translation and quaternion (SLERP) between mocap samples only with bracket gap <=50 ms; no extrapolation. 613 RGB, 595 depth, 2335 poses. 552 eligible cameras; metadata-only exclusions (61) are enumerated. Rank mod 6=0 gives F=92; remaining C=460. No subsequent shrinking/reselection of the camera domain. Full-domain video follows all 552 cameras in timestamp order at 24 fps; missing raw cameras are documented, not hidden. Metrics separately identify F and C, motion and invalid pixels. Depth timestamps use their own interpolated mocap poses for fusion; projection at RGB times accounts for asynchronous sensing. Pixel registration is approximate during motion.

RAW audit: initial reads are only rgb.txt, depth.txt, groundtruth.txt. Pixel access begins only after protocol and inputs hashes are sealed. Role-specific irreversible Linux Landlock allowlists cover native opens. Training/init sees only staged F RGB and F poses, never the RAW directory; builder sees only F sensor depth and F pose metadata. Evaluator can read C sensor depth only after model/asset SHA256 seals. Every permitted RAW read logs role, split, exact path, bytes and SHA256; native denial probes must confirm F/C depth inaccessible in training and C depth inaccessible in builder. ## Independent mechanism, fixed before C

F sensor-depth valid operational range [.3,4] m, discard zero and two-pixel invalid/border neighbourhoods. Cheap first pair is F ranks 0 and 1; pair checks project into depth-time poses, categorize consistent (|dz|<=max(.03,.02*z)), occluded (predicted behind observed beyond tolerance), contradiction (in front), unknown invalid/outside. Retain full counters including failures. No C used for thresholds. Multi-view point cloud only: backproject F depth stride 4, voxel .01 m, temporal supports from at least three F cameras. Structure candidate is near-side depth discontinuity >.06 m away from invalid neighbourhoods; contour extraction and .005 m world simplification form polylines. Filter motion/dynamic/noisy candidates using F multi-view visibility: >=3 depth-consistent views per point, contradictions <=20% of known views. Curve survives if >=60% points satisfy that rule and >=5 controls, length >=.05 m; rejected points break connectivity, never bridge a hole. Deterministic ID from source frame/contour/segment, max 500 curves in source order, fixed .007 m world diameter. Voxel fusion supplies occlusion and support, not a surface/mesh. No RGB, GS depth, D/I/L loss, C or trajectory-dependent relocation enters construction. Empty/weak survival is FAIL; no threshold search.

Store JSON + NPZ world controls, widths, unique IDs and consecutive-control topology, provenance and hashes. Seal before evaluator C reads. Edit the first surviving curve: move all its controls +.02 m along world X, double its width, retain ID/topology, create a separately hashed edited asset. Reproject original and edit across every camera; renderer must leave asset buffers byte-identical. Identity is defined by world data, not frame detection/linking.

Occlusion at C/trajectory uses projection of the fixed fused F point cloud, z-buffer stride4 with fixed 5x5 minimum fill; curve visibility tolerance max(.03,.02*z), unknowns explicitly counted. Never use C sensor depth to hide method strokes. For evaluation only, C sensor depth determines occlusion correctness and per-frame depth2d discontinuity upper-reference, not a build input. Invalid evaluation pixels do not count as success. Frame depth2d has no persistent 3D identity and is a visual reference, not an asset competitor. RGB-only frozen GS reference: C RGB rendering + per-frame RGB Canny (100,200); no fixed 3D asset, weak baseline, cannot imply defeated old I. Sensor depth2d, GS RGB and fixed sensor-3D are labelled in all panels. GS sensor depth is never equated; no sensor-depth supervision in GS training.

## Frozen pass/fail, visuals and reporting

Engineering pass requires trained sealed vanilla model, proven RAW boundary, projection/occlusion/alignment/identity/edit tests, reproducible asset JSON/NPZ, full video decode and bounded disk usage. Mechanism pass requires >=10 curves; >=50% of proposed contour length survives F filtering; >=80% evaluated C visible control samples have sensor support within tolerance; false-visible/occluded rate <=10% known C samples; at least one fixed ID disappears behind an occluder then reappears; edit effect reprojects in >=2 C views. Independent-camera sensor errors are grey areas and cannot be tuned away.

Stability measurement is identity survival/visibility correctness, not a low-ink flicker score. Report all camera ink distributions (p0,p10,p25,p50,p75,p90,p100), empty-frame fraction, curves/controls visible, and depth2d/GS-RGB ink ratios. If median ink ratio to either reference is outside [.5,2] or >20% C frames empty, forbid stable-superiority claims even if other gates pass. Baselines are weak and these thresholds alone do not establish perceptual quality. No independent human review exists.

Deliver all-domain CPU encoded video with fixed 3D, frozen-GS RGB edges, evaluation sensor depth2d and edit; multiple temporal quantile static frames (0,10,25,50,75,90,100%) and lowest/highest ink, side-by-side plus GS/RGB rendering evidence. Mark cuts (>0.15 s gap), occlusion/reveal ID observations and sensor invalid support. View images first; report failures without retuning. If evidence does not satisfy every scientific gate: NO-GO/FAIL or INCONCLUSIVE, never GO. A BLOCKED prerequisite stops downstream output rather than presenting placeholders as experiments.
