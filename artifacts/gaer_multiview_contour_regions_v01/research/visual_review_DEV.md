# 独立 DEV 初步视觉审阅：Lego / width 0.4

本次只查看已经允许开封的 [Lego 四个 DEV 视角](../media/lego/dev/width_0.4.png)：r_89、r_58、r_74、r_64。没有查看本轮 reserved 或 33arc 图像，没有查看其他 width 结果，没有提出或执行参数救援。图像 SHA256：`c67c8b66ec37bce2cc6974d4bab142a92e6fde329e7280e65f51221675bfe0dd`。这是未选定最终资产之前的初步观察，不代替两场景最终视觉判定。

**当前图能清楚辨认 Lego 物体的大体形状，但不支持“已经得到更可读的完整三维轮廓模型”。主要失败是车身、铲斗等部分变成大面积实心投影，许多线与部件的区分被面填充覆盖。** 轮廓边界更连续与轮廓结构更可读是两件事；本图主要呈现前者和物体剪影辨识，而非后者。

|r_64|主体竖向外形与底板外围较稳定可辨。|车体内部区分最弱之一，许多部件合成大块投影，只剩少量小白洞；底板仍有网状填充。|

图中并非完全没有负空间：支架开口、齿间缺口和底板部分白区仍存在。因此不能简单写成“全部变黑”。更准确的失败描述是：**局部负空间尚存，但大块面填充已占据主要视觉结构，粗轮廓不能从区域块中清楚分离。** 本图缺少同相机原 RGB/旧 thin/widened 对照，不能单凭它判断具体孔洞是否错误关闭，也不能量化新法相对基线的最终增益。

## 与当前数值记录的一致性及不可推断事项

读取的 `lego_region_multi24_0p4.json` 记录 119704 顶点、242184 三角面、182 个六邻域组件、99604 occupied voxels。大量三角面或较大连通体只说明确有固定区域几何，不证明轮廓正确；仍有 182 个组件也意味着“看起来是实心块”不等于数学上只有一个完整连通资产。

`lego_fusion_multi24.json` 的 164600 个候选约为原模型 310475 核的 53.0%。其中 single-source 为 39958（24.3%），multi-source 为 124642（75.7%）。因此，当前面域现象不能主要归因于“只有单视角支持的核太多”；不同方向的轮廓支撑空间 union 本身就可能覆盖更大表面域，另有既定尺度膨胀、体素下限和 closing 的影响。现有单臂图不能分别确定这些因素各自的因果贡献。

来源视角 captured rim mass 约 .980–.990，与高覆盖候选域相容，但支持质量不是干净轮廓质量。本轮最重要的负证据是视觉上大块面填充，不能用 captured mass 高来覆盖它。`width_world_floor=0.0054304` 也不是最终局部厚度；既定三维各向异性、score、尺度下限和投影叠加均影响实际宽度。

当前融合对各视角取 max：某个核在一个或少数视角有较强 rim 响应，便可保留该强度；它在其他可见视角投到物体内部不会降低这个最大值。因此“被多个视角观察/支持”与“在多个视角都只产生轮廓区域”不同，multi-source 比例高仍不保证内部干净。这是冻结规则自身的性质，不是根据本图提出的新补救规则。孔隙依然存在也只说明没有全部填实，不能把它当作优质轮廓的充分条件。

该图只用固定 mesh 的 self-zbuffer，对原物体仍为 x-ray。底板与内部杂密图案可能包含后方区域的投影，不能仅凭此图认证所有交叉都是真实三维误连，也不能称隐藏线问题已解决。

## 当前判定与后续读取边界

初步视觉状态：**物体形状可辨；局部外边界连续；作为以轮廓为主的可读模型尚未通过，面填充问题明显。** 这不是 renderer 无效或执行失败，也不是本轮所有宽度/两场景的最终 NO_GO。真实流水线应按冻结协议继续完成各臂、DEV 选择、资产 seal、保留集和完整视频，保留这些失败帧。

等待 root 确认固定资产 seals 后，再在被允许的 reserved/arc 证据上独立判断。最终应重点看外形恢复是否伴随可读线结构，是否以填实大面获得覆盖，负空间是否保留，以及完整相机序列中的稳定性；本审阅不会据这张 DEV 图提出后验门槛或参数修改。
